## 配置文件概览

项目中有三个环境变量配置文件：

| 文件路径 | 用途 | 使用场景 |
|---------|------|---------|
| `.env` (根目录) | Docker Compose 环境变量 | **Docker 环境（推荐）** |
| `backend/.env` | 后端应用环境变量 | 本地开发（不使用 Docker） |
| `frontend/.env.local` | 前端应用环境变量 | 本地开发（不使用 Docker） |

> **重要提示**：
> - `.env.example` 文件是模板文件，不会被实际使用
> - 实际使用的是 `.env` 文件（需要手动创建）
> - `.env` 文件已在 `.gitignore` 中，不会被提交到版本控制

## Docker 环境配置（推荐）

### 为什么推荐 Docker 环境？

- ✅ **配置简单**：只需配置一个 `.env` 文件
- ✅ **环境一致**：开发、测试、生产环境完全一致
- ✅ **依赖隔离**：无需在本机安装 Python、Node.js 等依赖
- ✅ **快速启动**：一键启动所有服务

### 配置步骤

#### 1. 初始化项目

```bash
# 运行初始化命令（会自动创建 .env 文件）
make init

# 或者手动创建
cp .env.example .env
```

#### 2. 编辑 `.env` 文件

打开根目录的 `.env` 文件，填写必要的配置：

```bash
# 最小化配置（快速开始）
SECRET_KEY=your-secret-key-change-this-in-production
NEXTAUTH_SECRET=your-nextauth-secret-change-in-production
TMDB_API_KEY=your-tmdb-api-key
DEEPSEEK_API_KEY=your-deepseek-api-key
```

> **提示**：其他配置项使用默认值即可，后续可根据需要调整。

#### 3. 启动服务

```bash
# 启动所有服务
make up
# 或
docker-compose up -d

# 初始化数据库
make migrate
# 或
docker-compose exec backend alembic upgrade head
```

#### 4. 访问应用

- 前端：http://localhost:3000
- 后端 API：http://localhost:8000
- API 文档：http://localhost:8000/docs

### Docker 环境变量传递机制

在 Docker 环境中，环境变量的传递流程如下：

```
.env (根目录)
    ↓
docker-compose.yml
    ↓
容器环境变量
    ↓
应用程序读取
```

**示例**：

```yaml
# docker-compose.yml
services:
  backend:
    environment:
      - DATABASE_URL=${DATABASE_URL}  # 从 .env 读取
      - REDIS_URL=${REDIS_URL}
```

## 本地开发环境配置

如果你不使用 Docker，需要分别配置后端和前端的环境变量。

### 后端配置

#### 1. 创建 `backend/.env` 文件

```bash
cd backend
cp .env.example .env
```

#### 2. 编辑 `backend/.env`

```bash
# 应用配置
APP_ENV=development
DEBUG=true
SECRET_KEY=your-secret-key

# 数据库配置（本地）
DATABASE_URL=postgresql://yueying:password@localhost:5432/yueying

# Redis 配置（本地）
REDIS_URL=redis://:password@localhost:6379/0

# MinIO 配置（本地）
MINIO_ENDPOINT=localhost:9000
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=minioadmin123
MINIO_SECURE=false

# JWT 配置
JWT_SECRET_KEY=your-jwt-secret-key
JWT_ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=30

# 第三方 API
TMDB_API_KEY=your-tmdb-api-key
GOOGLE_BOOKS_API_KEY=your-google-books-api-key

# LLM API
DEEPSEEK_API_KEY=your-deepseek-api-key
DEFAULT_LLM_PROVIDER=deepseek
```

#### 3. 启动后端

```bash
# 使用 uv（推荐）
uv venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
uv pip install -r requirements.txt
uvicorn app.main:app --reload

# 或使用 pip
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

### 前端配置

#### 1. 创建 `frontend/.env.local` 文件

```bash
cd frontend
cp .env.example .env.local
```

#### 2. 编辑 `frontend/.env.local`

```bash
# API 配置
NEXT_PUBLIC_API_URL=http://localhost:8000/api

# NextAuth 配置
NEXTAUTH_URL=http://localhost:3000
NEXTAUTH_SECRET=your-nextauth-secret
```

#### 3. 启动前端

```bash
# 使用 pnpm（推荐）
pnpm install
pnpm dev

# 或使用 npm
npm install
npm run dev
```

## 环境变量详细说明

### 应用配置

| 变量名 | 说明 | 默认值 | 必需 |
|--------|------|--------|------|
| `APP_ENV` | 应用环境 | `development` | 否 |
| `DEBUG` | 调试模式 | `true` | 否 |
| `SECRET_KEY` | 应用密钥 | - | **是** |
| `LOG_LEVEL` | 日志级别 | `INFO` | 否 |

### 数据库配置

| 变量名 | 说明 | 默认值 | 必需 |
|--------|------|--------|------|
| `POSTGRES_USER` | 数据库用户名 | `yueying` | 是 |
| `POSTGRES_PASSWORD` | 数据库密码 | `yueying_dev_password` | 是 |
| `POSTGRES_DB` | 数据库名称 | `yueying` | 是 |
| `DATABASE_URL` | 数据库连接字符串 | 自动生成 | 是 |

**连接字符串格式**：
```
postgresql://用户名:密码@主机:端口/数据库名
```

### Redis 配置

| 变量名 | 说明 | 默认值 | 必需 |
|--------|------|--------|------|
| `REDIS_PASSWORD` | Redis 密码 | `yueying` | 是 |
| `REDIS_URL` | Redis 连接字符串 | 自动生成 | 是 |
| `REDIS_MAX_MEMORY` | Redis 最大内存 | `512mb` | 否 |

**Redis 内存配置说明**：

- 开发环境：`256mb`
- 生产环境（小型）：`512mb`
- 生产环境（中型）：`1gb`
- 生产环境（大型）：`2gb+`

**连接字符串格式**：
```
redis://:密码@主机:端口/数据库编号
```

### MinIO 配置

| 变量名 | 说明 | 默认值 | 必需 |
|--------|------|--------|------|
| `MINIO_ROOT_USER` | MinIO 用户名 | `minioadmin` | 是 |
| `MINIO_ROOT_PASSWORD` | MinIO 密码 | `minioadmin123` | 是 |
| `MINIO_ENDPOINT` | MinIO 端点 | `minio:9000` | 是 |
| `MINIO_ACCESS_KEY` | 访问密钥 | 同 `MINIO_ROOT_USER` | 是 |
| `MINIO_SECRET_KEY` | 密钥 | 同 `MINIO_ROOT_PASSWORD` | 是 |
| `MINIO_SECURE` | 是否使用 HTTPS | `false` | 否 |

### JWT 配置

| 变量名 | 说明 | 默认值 | 必需 |
|--------|------|--------|------|
| `JWT_SECRET_KEY` | JWT 密钥 | - | **是** |
| `JWT_ALGORITHM` | JWT 算法 | `HS256` | 否 |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | 访问令牌过期时间（分钟） | `30` | 否 |
| `REFRESH_TOKEN_EXPIRE_DAYS` | 刷新令牌过期时间（天） | `7` | 否 |

### NextAuth 配置

| 变量名 | 说明 | 默认值 | 必需 |
|--------|------|--------|------|
| `NEXTAUTH_URL` | NextAuth URL | `http://localhost:3000` | 是 |
| `NEXTAUTH_SECRET` | NextAuth 密钥 | - | **是** |

### 第三方 API 密钥

| 变量名 | 说明 | 获取方式 | 必需 |
|--------|------|---------|------|
| `TMDB_API_KEY` | TMDB API 密钥 | [TMDB 官网](https://www.themoviedb.org/settings/api) | **是** |
| `GOOGLE_BOOKS_API_KEY` | Google Books API 密钥 | [Google Cloud Console](https://console.cloud.google.com/) | 否 |

### LLM API 配置

| 变量名 | 说明 | 获取方式 | 必需 |
|--------|------|---------|------|
| `DEEPSEEK_API_KEY` | DeepSeek API 密钥 | [DeepSeek 官网](https://platform.deepseek.com/) | 推荐 |
| `DEEPSEEK_BASE_URL` | DeepSeek API 端点 | `https://api.deepseek.com` | 否 |
| `OPENAI_API_KEY` | OpenAI API 密钥 | [OpenAI 官网](https://platform.openai.com/) | 可选 |
| `OPENAI_BASE_URL` | OpenAI API 端点 | `https://api.openai.com/v1` | 否 |
| `ANTHROPIC_API_KEY` | Anthropic API 密钥 | [Anthropic 官网](https://console.anthropic.com/) | 可选 |
| `ANTHROPIC_BASE_URL` | Anthropic API 端点 | `https://api.anthropic.com` | 否 |
| `DEFAULT_LLM_PROVIDER` | 默认 LLM 提供商 | `deepseek` | 否 |

**支持的 LLM 提供商**：
- `deepseek` - DeepSeek（推荐，性价比高）
- `openai` - OpenAI GPT
- `anthropic` - Anthropic Claude

### CORS 配置

| 变量名 | 说明 | 默认值 | 必需 |
|--------|------|--------|------|
| `CORS_ORIGINS` | 允许的跨域来源 | `http://localhost:3000,http://localhost` | 否 |

**格式**：多个来源用逗号分隔，例如：
```
CORS_ORIGINS=http://localhost:3000,https://yourdomain.com
```

### 速率限制配置

| 变量名 | 说明 | 默认值 | 必需 |
|--------|------|--------|------|
| `RATE_LIMIT_PER_MINUTE` | 每分钟请求限制 | `60` | 否 |
| `RATE_LIMIT_PER_HOUR` | 每小时请求限制 | `1000` | 否 |

### 文件上传配置

| 变量名 | 说明 | 默认值 | 必需 |
|--------|------|--------|------|
| `MAX_UPLOAD_SIZE_MB` | 最大上传文件大小（MB） | `10` | 否 |

## 常见问题

### Q1: 如何生成安全的密钥？

**方法 1：使用 Python**
```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

**方法 2：使用 OpenSSL**
```bash
openssl rand -base64 32
```

**方法 3：在线生成**
- https://generate-secret.vercel.app/32

### Q2: Docker 环境下如何修改配置？

1. 编辑根目录的 `.env` 文件
2. 重启相关服务：
   ```bash
   docker-compose restart backend frontend
   ```

### Q3: 本地开发环境如何连接 Docker 中的数据库？

修改 `backend/.env` 中的连接字符串：

```bash
# 将 postgres 改为 localhost
DATABASE_URL=postgresql://yueying:password@localhost:5432/yueying
REDIS_URL=redis://:password@localhost:6379/0
```

确保 Docker 服务已启动并暴露端口：
```bash
docker-compose up -d postgres redis minio
```

### Q4: 如何切换 LLM 提供商？

修改 `.env` 文件中的 `DEFAULT_LLM_PROVIDER`：

```bash
# 使用 DeepSeek
DEFAULT_LLM_PROVIDER=deepseek
DEEPSEEK_API_KEY=your-key

# 使用 OpenAI
DEFAULT_LLM_PROVIDER=openai
OPENAI_API_KEY=your-key

# 使用 Claude
DEFAULT_LLM_PROVIDER=anthropic
ANTHROPIC_API_KEY=your-key
```

### Q5: Redis 内存不足怎么办？

调整 `REDIS_MAX_MEMORY` 环境变量：

```bash
# 增加到 1GB
REDIS_MAX_MEMORY=1gb
```

然后重启 Redis：
```bash
docker-compose restart redis
```

### Q6: 生产环境部署需要注意什么？

1. **修改所有默认密码和密钥**
   ```bash
   SECRET_KEY=<生成强密钥>
   NEXTAUTH_SECRET=<生成强密钥>
   POSTGRES_PASSWORD=<强密码>
   REDIS_PASSWORD=<强密码>
   MINIO_ROOT_PASSWORD=<强密码>
   ```

2. **启用 HTTPS**
   - 配置 SSL 证书
   - 修改 `NEXTAUTH_URL` 为 HTTPS 地址
   - 设置 `MINIO_SECURE=true`

3. **调整资源限制**
   - 增加 `REDIS_MAX_MEMORY`
   - 配置数据库连接池大小
   - 调整 Nginx worker 进程数

4. **配置备份**
   - 定期备份数据库
   - 备份 MinIO 数据
   - 备份 `.env` 文件（安全存储）

5. **监控和日志**
   - 设置 `LOG_LEVEL=WARNING` 或 `ERROR`
   - 配置日志收集系统
   - 启用性能监控

### Q7: 如何查看当前使用的环境变量？

**Docker 环境**：
```bash
# 查看后端环境变量
docker-compose exec backend env | grep -E "DATABASE|REDIS|MINIO"

# 查看前端环境变量
docker-compose exec frontend env | grep NEXT_PUBLIC
```

**本地环境**：
```bash
# 后端
cd backend
source .venv/bin/activate
python -c "from app.core.config import settings; print(settings.dict())"

# 前端
cd frontend
npm run env
```

## 安全建议

1. **永远不要提交 `.env` 文件到版本控制**
   - 已在 `.gitignore` 中配置
   - 使用 `.env.example` 作为模板

2. **使用强密钥**
   - 至少 32 位随机字符
   - 包含大小写字母、数字和特殊字符
   - 定期轮换密钥

3. **限制 API 密钥权限**
   - 只授予必要的权限
   - 设置 IP 白名单（如果支持）
   - 监控 API 使用情况

4. **生产环境隔离**
   - 使用不同的密钥和密码
   - 不要在生产环境使用默认值
   - 使用密钥管理服务（如 AWS Secrets Manager）

## 🐳 Docker 环境（推荐）

### 配置方式

**只需要配置根目录的 `.env` 文件！**

```bash
# 1. 复制配置模板
cp .env.example .env

# 2. 编辑 .env 文件，填写必要的配置
vim .env  # 或使用其他编辑器

# 3. 启动服务
make up
```

### 工作原理

- Docker Compose 读取根目录的 `.env` 文件
- 通过 `docker-compose.yml` 中的 `environment` 字段传递给各个容器
- 后端和前端容器直接使用这些环境变量
- **不需要** 单独配置 `backend/.env` 或 `frontend/.env.local`

```bash
vim .env
```

- `SECRET_KEY`

- `NEXTAUTH_SECRET`

## ❓ 常见问题

### Q1: 为什么有多个 .env 文件？

**A:** 
- **Docker 环境**：只需要根目录的 `.env`
- **本地开发**：需要 `backend/.env` 和 `frontend/.env.local`
- 推荐使用 Docker 环境，配置更简单

### Q2: 如何生成安全的密钥？

**A:** 使用以下命令生成：
```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

### Q3: 不填写第三方 API Keys 会怎样？

**A:** 
- 不影响核心功能（记录管理、统计等）
- 无法使用探索功能（搜索外部内容）
- 无法使用 AI 功能（自动标签、推荐、助手等）

### Q4: 如何切换 LLM 提供商？

**A:** 修改 `.env` 中的 `DEFAULT_LLM_PROVIDER`：
```bash
DEFAULT_LLM_PROVIDER=siliconflow  # 或 deepseek, openai, claude
```

### Q5: 如何备份配置？

**A:** 
```bash
# 备份配置文件（注意：包含敏感信息，妥善保管）
cp .env .env.backup

# 或使用加密备份
tar czf env-backup.tar.gz .env
gpg -c env-backup.tar.gz  # 加密
```

### Q6: 生产环境部署需要注意什么？

**A:** 
1. 修改所有默认密码和密钥
2. 设置 `APP_ENV=production` 和 `DEBUG=false`
3. 使用强密码（至少 16 位，包含大小写字母、数字、特殊字符）
4. 配置 HTTPS（修改 Nginx 配置）
5. 定期备份数据库和配置文件
6. 考虑使用密钥管理服务（如 AWS Secrets Manager）

### Q7: 如何查看当前配置是否正确？

**A:** 
```bash
# 查看服务状态
make ps

# 查看后端日志
make logs-backend

# 查看前端日志
make logs-frontend

# 检查健康状态
make health
```

## 🔒 安全提示

1. **永远不要**将 `.env` 文件提交到 Git
2. **定期更换**密钥和密码
3. **使用强密码**（至少 16 位）
4. **妥善保管**备份文件
