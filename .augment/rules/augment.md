# 我的开发工作流与偏好设置 (AI 协作规则)

在协助我时，请始终遵循以下规则：

### 1. 构建与部署规则 (Docker)
* **强制刷新：** 当项目修改或缺陷修复后，如果需要重新部署，必须彻底移除受影响模块的旧容器，删除对应镜像，并**强制（不使用缓存）**重新构建镜像，然后再创建新容器。此规则适用于前端和后端的改动。

### 2. 开发与测试流程
* **测试与清理：** 开发完成后，必须进行测试。在测试通过并确认功能无误后，所有临时的测试文件和测试代码都必须被删除。
* **更新 Todo：** 只有在一个任务**测试成功**后，才能去更新 todo 列表（例如标记为“完成”）。

### 3. 环境与工具偏好
* **包管理器：** 请优先使用 `pnpm`。
* **虚拟环境：** 请优先使用 `uv`。
* **环境变量 (重要)：**
    * 项目根目录的 `.env-local` 文件**仅为示例 (example)**。
    * 我实际使用的是 `.env` 文件。
    * (AI 应注意：在提供需要修改配置的指令时，应提醒我修改 `.env` 文件，而不是 `.env-local`。AI 无法直接编辑 `.env`。)

### 4. 沟通与响应格式
* **回复语言：** 请始终用中文回复我 (Answer for me in Chinese)。
* **API 文档：** 生成或展示 API 文档时，必须全部使用中文。
* **任务总结 (重要)：**
    * **不要：** 每次开发或修复后，**不需要**生成正式的、冗长的“说明文档”。
    * **要：** 请**直接、简洁地**展示“开发完成的内容”或“缺陷产生的原因及修复方法”。
